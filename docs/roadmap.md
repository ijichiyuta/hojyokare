# ホジョカレ 開発ロードマップ

作成: 2026-08-15。優先順位の考え方: **無料チェッカーが唯一の集客装置であり、かつ全機能が期限計算エンジンに依存する**ため、
認証もDBもほぼ不要な Phase 1 を最小リリースとして先行させ、リード獲得を回しながら有料機能を積む。

## Phase 0: 基盤決定(半日)

- [ ] 技術スタック決定(フレームワーク/DB/ホスティング/メール基盤)
- [ ] プロジェクトスキャフォールド、Lint/テスト/CI、デプロイ確認

## Phase 1: 無料チェッカー + LP(最小リリース)

リリース条件: 認証なしで「入力→計算→結果表示→PDF/メール」が完結し、リード(メールアドレス)が保存されること。

1. **制度マスタ設計** — 補助金種別×公募回→期限ルールのデータ構造(まずコード内マスタでよい)
2. **期限計算エンジン** — 純関数+単体テスト。実績報告/事業化状況報告×5年/財産処分制限期間。根拠(資料名・版・ページ)もマスタから返す
   - ⚠️ 着手前に公募要領・事務処理マニュアルで正式ルールを検証(モックに 04/30 vs 06/30 の不整合あり → docs/requirements.md 参照)
3. **チェッカー入力画面** — 6項目フォーム+バリデーション
4. **計算結果画面** — 期限グループ3種+根拠+免責表示
5. **PDF出力** — 結果のPDF化
6. **メール送付+リード保存** — 結果送付。ここで初めてDBが必要(リードテーブル)
7. **30日前無料アラート** — 日次バッチ(cron)で該当リードに1通送信
8. **LP** — デザイン通りに実装、チェッカーへ誘導
9. 法的ページ(利用規約/プライバシーポリシー/特商法表記)※リリースまでに

## Phase 2: 認証+有料管理画面コア

1. 認証・組織・メンバー管理(管理者/担当者ロール、招待)
2. 案件CRUD+制度マスタからの期限自動生成、期限の手動上書き+履歴
3. ダッシュボード(KPI/案件×期限マトリクス/直近90日)
4. 段階リマインド 90/60/30/14/7/前日(まずメールのみ、通知設定マトリクス)
5. 決済(Stripe想定): プラン/案件数上限/請求書

## Phase 3: 証憑・チェックリスト・LINE

1. 証憑ボックス(ストレージ、論理削除+操作ログ、15分署名付きURL)
2. 報告サイクル別チェックリスト(制度マスタ連動、揃った/確認中/未収集)
3. 不足分まとめ催促(メール→LINE)
4. LINE連携(Messaging API): リマインド送信、証憑受信、自動仕分け ※LINE公式アカウント開設が前提

## Phase 4: 士業パートナー

1. 事務所アカウントと顧問先の紐付け(招待リンク・有効期限)
2. 顧問先横断ダッシュボード+一括CSV出力
3. 白ラベル通知(事務所名・事務所アドレスで送信)
4. 従量課金(20案件超過分)
